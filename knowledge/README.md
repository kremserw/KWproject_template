# Knowledge Repository

This is the persistent knowledge base — the **ingest layer** of the project. Agents read from and
write to this folder to avoid redundant work across sessions. Content is append-only and cross-linked;
the structure itself is refined over time (the double-loop / infrastructure idea).

## Top-level files

- **LESSONS.md** — shared pitfall & guardrail register (failure-derived lessons). Read before any
  KB-maintenance or writing pass; the linter reads and enforces it.
- **LINK-GRAPH.md** — cross-link graph across knowledge files (regenerated by the linter).

## Structure

- **foundations/** — the stable, given-from-outside facts that define the project's scope: the
  program / mandate / central research question / analytic framework. The bedrock everything builds on.
- **project-management/** — project operations as knowledge: team, budget, timeline, governance,
  stakeholders. (Distinct from the live tracking dashboards at the repo root.)
- **units/** — per-{{UNIT_NOUN}} knowledge (one subfolder per {{UNIT_NOUN}}). A "unit" is the repeatable
  atom of work for this project type — scaffold one with `/new-unit`.
- **domain/** — external research synthesis (durable findings, theory, institutional practice)
  - `landscape/` — dated snapshots of the fast-moving external environment (one file per {{SNAPSHOT_CADENCE}} period)
- **outreach/** — outward-facing materials (what the project sends out: descriptions, briefings, memos)
- **sources/** — raw archived inputs, organized by type
  - `articles/` — academic papers, news articles, web content
  - `deepresearch/` — AI deep research reports (GPT, Claude, …)
  - `official/` — official / primary documents, regulations, protocols
  - `materials/` — slides, syllabi, books, datasets; bundle subfolders each carry an `_index.md`

## Navigation

Each non-empty folder has a `_summary.md` file with a contents table, key facts, and connections to
other folders. Read `_summary.md` first to orient, then drill into specific files as needed.

**Convention — `_summary.md` vs. `_index.md`:**
- `_summary.md` is used for folders that contain multiple semantic knowledge files.
- `_index.md` is used inside `sources/materials/<bundle>/` subfolders as a bundle-level manifest
  listing raw archival inputs. It serves the same orientation role for raw-source bundles.

## Rules

- Never delete content from this folder.
- Always append with a dated header when adding to an existing file.
- If a source is already recorded, do not re-fetch it.
- When adding new files, update the folder's `_summary.md` accordingly.
- Tag new entries with the Source/Verification/Confidence triplet (see `CLAUDE.md`).
